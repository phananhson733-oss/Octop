## 1. Ownership and actual chain

1. `research_keywords` performs provider research and persists/cache metrics; returns rows. It does not save rows to the user's curated saved-keyword list automatically.
2. `save_keywords` writes curated keyword membership, optional supplied metrics and tags. It does not call DataForSEO or an LLM.
3. An **external agent** follows `keyword-research` and `seo-report` Markdown skills to interpret evidence and **generate the complete HTML**.
4. `save_report` receives HTML/title/summary, validates limits/project/template and stores it. **It does not generate HTML, call an LLM, hydrate data, or append research logs automatically.** Those are agent workflow actions.
5. Source SAM intentionally has no report tools; native Octop should use its own agent+artifact flow instead of reproducing this source limitation.

## 3. Persistence, identity, timestamps and tags

- Saved membership unique key is `(projectId, normalized keyword, locationCode, languageCode)`. Insert has random UUID, creation time and `ON CONFLICT DO NOTHING`, then reads matched rows. Repeat preserves membership ID and createdAt; another country/language or project creates distinct membership. No device or local locationName in this membership identity. [Schema unique key](https://github.com/every-app/open-seo/blob/d7ea7852480601af9bc8870942af8311a410e567/src/db/app.schema.ts#L87-L113), [insert/readback](https://github.com/every-app/open-seo/blob/d7ea7852480601af9bc8870942af8311a410e567/src/server/features/keywords/repositories/KeywordResearchRepository.ts#L117-L140).
- Metrics live separately, with the same project+keyword+country+language unique key. Save accepts caller-supplied fields; absent fields in a supplied metric become null, absent monthlySearches becomes `[]`; it overwrites the entire metric field set. It stamps `fetchedAt` to **save-time now**, even if the supplied metrics came from old research. Without metrics, save preserves existing metrics. Metrics not in selected keywords are ignored. [Metric handling](https://github.com/every-app/open-seo/blob/d7ea7852480601af9bc8870942af8311a410e567/src/server/features/keywords/services/research/saved-keywords.ts#L41-L77), [upsert/timestamp](https://github.com/every-app/open-seo/blob/d7ea7852480601af9bc8870942af8311a410e567/src/server/features/keywords/repositories/KeywordResearchRepository.ts#L61-L105).
- Important native provenance difference: keep providerObservedAt/original researchRunId/requestHash separate from savedAt. Never mark metric copy as fresh provider fetch. For faithful expanded market support, local-volume origin needs separate locationName/metric scope: original membership schema does not carry it, though research can return local volume. National-only first slice can explicitly disable local selection instead of incorrectly labelling local volume national.
- Tags unique `(projectId, normalizedName)`; display spelling/case comes from first creation, subsequent upsert is no-op; keyword-tag pair unique. Normalize name by trim+collapse whitespace, identity lowercased. Append forms union. Replace first ensures desired assignments then deletes other assignments **only from exact project-scoped saved rows returned for selected country/language**; it does not delete tag entities or change another market's keyword tags. [Tag normalization](https://github.com/every-app/open-seo/blob/d7ea7852480601af9bc8870942af8311a410e567/src/shared/saved-keyword-tags.ts#L8-L28), [append/replace](https://github.com/every-app/open-seo/blob/d7ea7852480601af9bc8870942af8311a410e567/src/server/features/keywords/repositories/SavedKeywordTagsRepository.ts#L116-L185), [tag upsert](https://github.com/every-app/open-seo/blob/d7ea7852480601af9bc8870942af8311a410e567/src/server/features/keywords/repositories/SavedKeywordTagsRepository.ts#L254-L287).
- Original service operations span metric upserts, saved-membership batch, and tags with no surrounding all-operation transaction. Called directly with replace/no tags, the service rejects only after saving membership. Native should validate normalized selections/tags before any write and transact local membership/metrics/tags. This deliberately fixes partial-write behavior; it should be labelled rather than copied.

## 4. Report generation versus storage

`seo-report` is a **writing workflow**, not a report-generation API. It asks the agent to list reports before writing; same subject+period should reuse a reportId, different month/competitor/skill creates a new report. The agent resolves templates, reads project writing preferences, generates finished HTML and summary, then saves. Templates apply only when user names one or requested report type matches; template sections/tone override producing skill output, while HTML constraints remain. [Preparation/template](https://github.com/every-app/open-seo/blob/d7ea7852480601af9bc8870942af8311a410e567/plugins/openseo/skills/seo-report/SKILL.md#L14-L24).

Keyword report sections: opportunity; target-now table including keyword/intent/volume/KD/CPC/page recommendation; supporting reasoning; longer opportunity list; risks/caveats (unknown values/shared-volume buckets); next actions; final how-made section. Metrics and inferred recommendations must remain distinguishable; no deterministic source algorithm produces the recommendations. [Producing skill report outline](https://github.com/every-app/open-seo/blob/d7ea7852480601af9bc8870942af8311a410e567/plugins/openseo/skills/keyword-research/SKILL.md#L63-L83).

In native product, copying a skill's instructions is not an enforceable runtime write authorization; bind execution to user-initiated save intent/selected rows or existing authorized agent scope. ## 5. save_report validation, attribution, idempotency and readback

Input: projectId, nonempty title, nonempty markdown summary, complete nonempty html; optional nonempty reportId (update), optional skill max60 chars, optional nonempty project-owned templateId. No data generation occurs. Creator client label/user identity are derived from authenticated context, never model-supplied. [Tool schema](https://github.com/every-app/open-seo/blob/d7ea7852480601af9bc8870942af8311a410e567/src/server/mcp/tools/report-tools.ts#L61-L102), [template/creator handling](https://github.com/every-app/open-seo/blob/d7ea7852480601af9bc8870942af8311a410e567/src/server/mcp/tools/report-tools.ts#L128-L151).

Limits: UTF8 HTML bytes<=500000; title `.length`<=120; summary `.length`<=2500; skill<=60; project max10000 reports on create only; organization total HTML bytes<=5e9 including net size delta of update. Report list MCP default20/max50; app latest100. Source `.length` means JS UTF16 code units, unlike Python codepoints; decide an explicit documented Unicode interpretation when porting. [Constants](https://github.com/every-app/open-seo/blob/d7ea7852480601af9bc8870942af8311a410e567/src/types/schemas/reports.ts#L13-L37).

Actual service HTML check is only `html.trim().toLowerCase().includes('<html') && endsWith('</html>')`. It does **not** parse HTML, validate matching title/h1, enforce no scripts/resources, reject backticks or `${`, or generate metadata. UTF8 size check comes first. Better native document checks/sandbox are intentional additions, and source skill no-template-literal restriction is a client transport instruction, not a Python/API domain constraint. Title date/style recommendations are agent instructions, not service validation. [Actual validation](https://github.com/every-app/open-seo/blob/d7ea7852480601af9bc8870942af8311a410e567/src/server/features/reports/services/ReportService.ts#L55-L114), [skill HTML constraints](https://github.com/every-app/open-seo/blob/d7ea7852480601af9bc8870942af8311a410e567/plugins/openseo/skills/seo-report/SKILL.md#L37-L65).

Source saves:

- With no reportId: generate UUID, write supplied content, skill/template null if omitted; new reports private; createdAt=updatedAt=server ISO UTC now. Same exact title within same project is refused; no trim/lowercase normalization on title. Title uniqueness is a **service read/check**, not DB unique constraint (schema has updated-index/share-token uniqueness only), so do not infer concurrent-create idempotency.
- With reportId: authorize same-project row; reject unknown/foreign ID and colliding title; update in place. Missing skill/template preserves stored values; creator attribution+createdAt preserved; updatedAt and size changed; sharing token preserved. Old HTML is gone, no version history, no ETag/expected version/content hash/optimistic-lock contract.
- Output `{reportId,title,created,htmlBytes,url,...meta}`. Reads default metadata+full summary only; `includeHtml=true` gets full stored HTML. Lists return truncated summary previews and no HTML; bulk list hides raw share tokens. If full HTML byte length differs from stored byte count, skill says never save truncated read back over good report.

[Create/update](https://github.com/every-app/open-seo/blob/d7ea7852480601af9bc8870942af8311a410e567/src/server/features/reports/services/ReportService.ts#L95-L183), [repository timestamps/unchanged attribution](https://github.com/every-app/open-seo/blob/d7ea7852480601af9bc8870942af8311a410e567/src/server/features/reports/repositories/ReportRepository.ts#L99-L182), [read projection](https://github.com/every-app/open-seo/blob/d7ea7852480601af9bc8870942af8311a410e567/src/server/mcp/tools/report-tools.ts#L285-L370), [schema indexes](https://github.com/every-app/open-seo/blob/d7ea7852480601af9bc8870942af8311a410e567/src/db/reports.schema.ts#L73-L84).

Native chosen improvement from approved plan: immutable report versions+staging/ready+hash+run lineage. Same logical report can receive a new version; prior content/approved versions survive. Define idempotency key (e.g. runId+content hash) and atomically unique version identity, rather than relying on list-before-create or title alone. A deterministic HTML renderer from evidence JSON is an acceptable native product choice, but call it a renderer; LLM synthesis still belongs to Octop's agent, and optional rendering/model spend must be distinct from save-only action.
