# 原生账号密码统一入口：离线 G0 候选

状态：仅测试候选，不是生产服务；不由 Octop app.py 挂载，不运行公网监听。

## 已选择的最小路线

用户要求保留账号密码体验。候选采用服务端显式身份目录：登录名映射到一个固定实例和一个已存在的用户 ID；密码仅送该实例的原生 /auth/login 校验。不会依次试多个实例，不合并同名账号，不导出或复制密码哈希。

客户端拿到不含实例凭据的随机入口令牌。入口会话保存实例绑定及实例访问令牌，请求中的租户字段不能改变绑定。每次请求先用原实例 /auth/me 检查账号和会话状态；实例滑动续期只保存在服务端，不透传客户端。

目录中的 internal/same_name、customer/same_name 是候选消歧名称，不是已经决定的正式登录名。正式迁移必须确认命名和原有用户名兼容映射。

## 可重复验证

在仓库根目录运行：

```sh
UV_PROJECT_ENVIRONMENT=/Users/wzb/Code/Octop/.venv PYTHONPATH=src \
  uv run --no-sync pytest tests/integration/test_unified_entry_candidate.py -q
```

测试启动两个真实 Octop ASGI 应用，使用临时 SQLite/文件目录，模型运行时为既有测试替身。候选入口也通过 ASGI 请求调用，不连接生产或外部身份服务。

覆盖：

- 同名但不同密码的账号由预登记目录准确定位，不猜测归属。
- 无绑定登录名拒绝；内部密码不能登录客户实例账号。
- 入口凭据不能直接作为实例 JWT 使用，不返回实例续期头。
- 内部实例实际安装一个插件，客户名单为空；入口返回各自不同数据。
- query/header 中伪造 instance/tenant 不改变登录绑定。
- 客户入口退出后该会话失效，内部会话继续有效。
- 实例停用用户后入口下一请求拒绝。

## 未完成的 G0 要求（禁止上线）

- 目录、会话和撤销状态已使用数据库持久化；后端令牌使用外部注入密钥加密并绑定入口令牌摘要。临时 SQLite 恢复/调换密文/迟到刷新测试通过；生产密钥保管、备份恢复、PostgreSQL 多进程验收及自动重试协调仍未完成。
- 已有持久化 identity disable 的领域方法，尚无管理界面、完整全局停用传播、授权期望版本/执行端回执或跨设备注销。
- 登录响应与 /me 已对齐原Dashboard，固定业务根HTTP代理接入agents/experts/tasks/threads/uploads/downloads/knowledge-bases/skills/plugins和少量只读配置；不是任意路径代理。输入与输出流每块重查中央会话，异常/取消/响应头断连关闭后端。真实双ASGI验证相同agent_id按实例隔离，mock下游流验证SSE/上传取消；尚未完整验收真实聊天、附件、便携下载链接和浏览器。WebSocket已接入固定后端聊天路径，传递native Authorization header而非URL令牌，禁重定向，双向逐帧及1秒空闲周期复核中央/后端身份；本地Uvicorn真实回环网络通过原生聊天协议和fake LLM，仍不等于真实浏览器/生产网络验收。
- 退出的 timeout 已作为待处理失败保留，仍未统一处理其他 upstream timeout、captcha、入口限流、固定 origin TLS 校验或完整部署恢复。测试客户端是预注入 ASGITransport，不能当作已完成真实网络验证。
- 入口固定有效期，不延长本身会话；原实例续期只更新内部凭据。正式会话期限、重登录与清理须定义。
- 原实例域名/直连 API 尚未统一到同一准入控制；本候选不提供全球权限保证。
- 未测真实浏览器的账号切换、缓存、Cookie、插件脚本和产物同源隔离。
- 登录错误细节统一，但未验证入口时序/枚举防护。全局 ID 必须稳定持久化，不能从客户端字段或临时测试编号推断。

因此本候选只回答“无需改变密码体验，是否能保留分库并统一入口请求归属”，不是整个 G0 已通过。继续落实方案其余门槛后才能进入迁移候选评审。


本候选撤销记录 pending/done 与加密会话独立保存，迟到刷新不能复活权限；done 后迟到写入可能留下不可用的加密残留，需要后续安全清理。后端新增签名凭据专用的幂等撤销接口；真实ASGI测试模拟提交后的204丢失，并通过新连接发现待处理记录、后台重试取得显式回执。reconcile_revocations 是分页处理例程，候选 lifespan 已每5秒调用一次并在末页回绕游标，关闭时停止新轮次并等待在途任务及数据库线程；测试证明无浏览器参与也能取得回执。仍未部署，需要生产退避/告警/密钥轮换策略。会话已改为专用 entry_sessions 表，state/session_key 联合索引定位pending，状态转换及清除凭据为原子更新。schema22 SQLite/PG迁移和水位修复已在候选验证。PostgreSQL17.6本地两池完成30轮撤销/续期交错，2万done行下查询走Index Only Scan；仍需真实部署容量与网络延迟验收。


schema22 是未发布实现的新迁移，只增加入口会话表与索引，不修改旧账号或业务内容。此前KV会话格式仅存在于临时测试数据库，未部署；新代码不把它当成生产迁移源。正式上线前仍需备份与完整恢复演练。


WebSocket候选依赖本次实际验证的 websockets 15.0.1 connect API，生产打包必须固定并验证兼容依赖。已有网络断开不会自动取消原生正在处理的任务（native支持断线续接）；关闭会话连接不等于所有后台工具副作用立即停止。中央/后端失效后的数据交付已在候选验证，任务取消归属仍需单独验收。


## 浏览器候选

`demo.py --sab-ui <现有 sab-tools/ui/index.js> --port 8768` 启动只监听loopback的合成环境，管理员随机私密密码，测试用户 `customer/demo` 和 `internal/demo` 使用测试密码 `TestPass12`。依赖原仓库测试替身，不能当成生产启动器；结束会清理临时数据库/文件。

使用 webapp-testing 的 with_server.py 管理生命周期并运行 inspect_browser.py。浏览器脚本验证真实登录滑块、专家、原选剧UI、测试模型回复、附件回执和字节读回。报告与截图在 docs/plans/evidence/browser。`--check-isolation` 只验证外部数据库/浏览器环境变量不会逃出临时目录，不启动服务。

当前单账号浏览器流程通过，尚未覆盖多标签身份切换、管理员批量开通、生产数据迁移和剪辑大文件验收。
